# redis-valkey

In-cluster backend for the `RedisInstance` XR (`cloud.example.org/v1alpha1`):
no cloud account, no VPC. Typed against the `helm` schema package
([`../../../providers/helm`](../../../providers/helm)), it renders one
provider-helm `Release` that installs the Bitnami Valkey chart into the XR's
namespace. Valkey speaks the Redis wire protocol, so a client configured for
the AWS or GCP backend works unchanged. The Composition (`redis-valkey`,
label `provider: valkey`) runs it through `function-kcl` from
`oci://docker.io/yurikrupnik/redis-valkey`, followed by `function-auto-ready`.

## Composed resources

| resource | when | notes |
| --- | --- | --- |
| `Release` (`helm.m.crossplane.io`) | always | composition-resource-name `managed`; chart `valkey` from `oci://registry-1.docker.io/bitnamicharts`, pinned in `redis.k` so a re-render never upgrades a running dataset; `providerConfigRef` is the `ClusterProviderConfig` `default` from [`../xrd/providerconfigs.yaml`](../xrd/providerconfigs.yaml); `wait: true`, `waitTimeout: 10m` |

`deletionPolicy: Orphan` sets `managementPolicies` to
`Observe, Create, Update, LateInitialize`, leaving the Helm release installed.

## Spec fields read

Full schema: [`../xrd/xrd.yaml`](../xrd/xrd.yaml). Chart values written:

| spec field | chart values |
| --- | --- |
| (XR name) | `fullnameOverride` |
| `replicas` (`0`) | `replica.replicaCount`; `architecture: replication` when > 0, else `standalone` |
| `highAvailability` | at least one replica (`replication`) even at `replicas: 0` |
| `memoryGb` (`1`) | memory request and limit on `primary` and `replica`; `maxmemory` default of 80% of it in MiB (headroom for the snapshot fork) |
| `parameters` | merged over the defaults `maxmemory` and `maxmemory-policy: allkeys-lru` (a user key wins), written to `commonConfiguration` as sorted `key value` lines |
| `authEnabled` (`true`) | `auth.enabled`; the chart generates the password |
| `transitEncryption` (`true`) | `tls.enabled` and `tls.autoGenerated` (self-signed), `tls.authClients: false` |
| `persistence` (`true`) | `persistence.enabled` on primary and replica |
| `persistenceSizeGb` (`8`) | `persistence.size`, `<n>Gi` |
| `tags` | `commonLabels` |
| `deletionPolicy` | `managementPolicies` (see above) |

Ignored: `region`, `engineVersion` (the chart's own default), `nodeType`,
`atRestEncryption`, `encryptionKmsKeyId`, `snapshotRetentionDays`,
`maintenanceWindow`, `network`.

Status written back to the XR. Endpoints are derived from the release name
and reported as soon as the chart is deployed: `host`
`<xr>-primary.<ns>.svc.cluster.local`, `port` 6379, `endpoint`,
`readEndpoint` (`<xr>-replicas…` when there is at least one replica, else the
primary), `url` (`rediss://` with transit encryption, else `redis://`),
`cloud-url` (`kubernetes://<ns>/statefulset/<xr>-primary`), `provider: valkey`.
With `authEnabled`: `authSecret: <xr>`, `authSecretKey: valkey-password`. From
the observed release (`status.atProvider`): `ready` (`state == deployed`),
`version`, and `id` (`<ns>/<xr>@<revision>`).

## Usage

```bash
# built-in example XR (`_example` in main.k: example in namespace default)
kcl run packages/cloud/redis/valkey

# a real XR, wrapped the way function-kcl passes it (`oxr`; `ocds` optional)
kcl run packages/cloud/redis/valkey \
    -D params="{\"oxr\": $(yq -o json -I0 packages/cloud/redis/xrd/examples/redis-valkey.yaml)}"
```

`ocds` takes observed composed resources keyed by composition-resource-name;
`ocds.managed.Resource.status.atProvider` is what the status block reads.

Against the Crossplane function, from the working tree (needs docker and the
`crossplane` CLI; renders
[`../xrd/examples/redis-valkey.yaml`](../xrd/examples/redis-valkey.yaml)):

```bash
pnpm exec nx run redis-valkey:render     # or: just render redis-valkey
```

On a cluster: `just e2e redis` (Kind cluster, publish, install, every
example), `just install-module redis` (XRD and Compositions only), or
`just workload redis valkey` on a running platform.

## Layout

| file | content |
| --- | --- |
| `main.k` | entry point: reads `option("params")`, falls back to `_example`, emits `render` + `status` |
| `redis.k` | `render`, `status`, chart pin, Service-name, config-line and merge helpers |
| `redis_test.k` | `kcl test` cases |
| `composition.yaml` | the `redis-valkey` Composition |

## Development

```bash
pnpm exec nx run redis-valkey:test     # kcl test
pnpm exec nx run redis-valkey:lint     # kcl lint
pnpm exec nx run redis-valkey:render   # crossplane render (needs docker)
```

`version` in `kcl.mod` is bumped by `nx release` in CI; do not edit it by hand.
