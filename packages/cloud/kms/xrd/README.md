# kms-xrd

The `EncryptionKey` XRD (`cloud.example.org/v1alpha1`, namespaced,
`encryptionkeys.cloud.example.org`): one portable managed encryption key that
other resources reference for encryption at rest or signing. The KCL schemas
under `models/` are generated from [`xrd.yaml`](xrd.yaml) by
`just xrd-schema kms` (`kcl import -m crd`); regenerate after every change to
`xrd.yaml` and do not hand-edit `models/`.

The key is named after the XR (`metadata.name`), so the name must satisfy the
strictest backend you target: Azure Key Vault names are 3-24 characters,
alphanumerics and dashes. Key material is never exported by the cloud backends.

## Spec

| field | type | required | default | meaning |
| --- | --- | :-: | --- | --- |
| `region` | string | ✓ | | AWS region / Cloud KMS location / Key Vault location / OCI region (oci binds to `ClusterProviderConfig` `oci-<region>`); ignored by openbao |
| `resourceGroup` | string | azure | | Existing resource group for the Key Vault |
| `tenantId` | string | azure | | Entra ID tenant that owns the Key Vault |
| `compartmentId` | string | oci | | OCID of the compartment the Vault and Key live in |
| `purpose` | `encrypt-decrypt` \| `sign-verify` | | `encrypt-decrypt` | `sign-verify` needs an asymmetric algorithm |
| `algorithm` | `symmetric` \| `rsa-2048` \| `rsa-3072` \| `rsa-4096` \| `ec-p256` \| `ec-p384` | | `symmetric` | `symmetric` is only valid with `encrypt-decrypt`; on Azure it becomes an RSA-4096 wrap key |
| `protectionLevel` | `software` \| `hsm` | | `software` | Ignored by aws (always HSM) and openbao (software barrier only) |
| `rotationDays` | integer ≥ 1 | | | Automatic rotation period; omit for none. AWS/GCP rotate symmetric keys only; ignored by oci |
| `deletionWindowDays` | integer 7-90 | | `30` | Grace period before key material is destroyed; ignored by oci and openbao |
| `multiRegion` | boolean | | `false` | AWS-only multi-region primary key |
| `exportable` | boolean | | `false` | OpenBao-only: allow reading key material back out |
| `mountPath` | string | | `transit` | OpenBao-only: transit mount the key lives in (shared, never deleted by an XR) |
| `deletionPolicy` | `Delete` \| `Orphan` | | `Delete` | `Orphan` keeps the external key (managementPolicies without `Delete`) |
| `tags` | map of string | | | AWS tags / Cloud KMS labels / Key Vault tags / OCI freeformTags; ignored by openbao |

Status: `ready`, `provider`, `keyName`, `region`, `keyId`, `keyUri` (what
encrypting clients reference), `cloud-url`, `algorithm`, `protectionLevel`,
`rotationEnabled`, `id`, plus backend-specific `arn`, `alias` (aws),
`keyRing` (gcp), `vaultUri`, `version` (azure), `vaultId`,
`managementEndpoint`, `cryptoEndpoint` (oci), `mountPath` (openbao). Printer
columns: `READY`, `PROVIDER`, `KEY-URI`, `CLOUD-URL`.

## Backends

An XR picks one with `spec.crossplane.compositionSelector.matchLabels.provider`.

| dir | Composition | `provider` label | composes |
| --- | --- | --- | --- |
| [`../aws/`](../aws/) | `kms-aws` | `aws` | KMS `Key` + `Alias` |
| [`../gcp/`](../gcp/) | `kms-gcp` | `gcp` | Cloud KMS `KeyRing` + `CryptoKey` |
| [`../azure/`](../azure/) | `kms-azure` | `azure` | Key Vault `Vault` + `Key` |
| [`../oci/`](../oci/) | `kms-oci` | `oci` | OCI `Vault` + `Key` |
| [`../openbao/`](../openbao/) | `kms-openbao` | `openbao` | OpenBao transit `Mount` + `SecretBackendKey` |

## Manifests

| file | content |
| --- | --- |
| `xrd.yaml` | The `CompositeResourceDefinition` |
| `providers.yaml` | `provider-aws-kms`, `provider-gcp-kms`, `provider-azure-keyvault`, `provider-vault` (upbound, v4.x namespaced CRDs), `provider-family-oci` + `provider-oci-kms`, and `provider-helm` with its cluster-admin ServiceAccount and `DeploymentRuntimeConfig`. Versions match the schema packages generated by `just seed-kms-providers` |
| `functions.yaml` | Pinned `function-kcl` and `function-auto-ready` |
| `providerconfigs.yaml` | Helm `ClusterProviderConfig`, the OpenBao Helm `Release` (standalone, file storage) and the vault `ClusterProviderConfig` reading Secret `openbao-token`; a commented OCI `ClusterProviderConfig` template. AWS/GCP/Azure configs need your own credentials |
| `examples/kms-<backend>.yaml` | One `EncryptionKey` per backend, annotated with the fields that backend ignores |

`providerconfigs.yaml` is applied only after the Providers are Healthy (its
kinds come from their CRDs). OpenBao starts sealed: its header comments list
the one-time `bao operator init` / `unseal` and the `openbao-token` Secret
(a JSON object `{"token": …}`, not a bare token).

## Usage

```bash
just e2e kms                       # kind cluster, publish, install, providers, providerconfigs, examples
just install-module kms            # XRD + all Compositions, repointed at the local registry
kubectl apply -f packages/cloud/kms/xrd/examples/kms-openbao.yaml
```

## Development

```bash
pnpm exec nx run kms-xrd:lint     # kcl lint
```

`version` in `kcl.mod` is bumped by `nx release` in CI; do not edit it by hand.
